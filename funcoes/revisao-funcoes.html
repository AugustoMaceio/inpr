Conceito

O que é uma função?

Uma função é um bloco de código com nome. A gente escreve uma vez e manda executar quantas vezes quiser, só chamando pelo nome.

🍹 A máquina de suco

Pensa numa máquina de suco: você coloca uma fruta (entrada), a máquina bate (processamento) e sai o suco (saída). Uma função é exatamente isso.

🍊 Entrada (argumento)➜ ⚙️ Processamento (corpo)➜ 🥤 Saída (return) 
function fazerSuco(fruta) {
    return `Suco de ${fruta}`
}
fazerSuco("laranja")

🥤 "Suco de laranja"

Traduzindo: a fruta é o argumento, o parâmetro fruta é a "boca" da máquina, o miolo entre as chaves { } é o processamento, e o return é o copo de suco que a máquina devolve para quem pediu.

Por que usar funções?

  • Não repetir código: escreveu uma vez, usa mil vezes.
  • Organizar: cada função faz uma coisa só, com um nome que explica o que ela faz.
  • Testar em partes: se der problema, você sabe em qual "maquininha" olhar.
  • Trabalhar em equipe: cada um cuida de uma função.
Estrutura

Anatomia de uma função

Clique (ou passe o mouse) em cada pedacinho do código para ver o que ele faz.

function somar(a, b) {
    return a + b
}

somar(4, 6)   // devolve 10

👆 Escolha uma peça

Cada parte da função tem um papel. Clique em function, no nome, nos parênteses, nas chaves ou no return.

O molde geral

// 1) DEFINIR a função (a receita fica guardada)
function nomeDaFuncao(parametro1, parametro2) {
    // corpo: o que a função faz
    return resultado
}

// 2) CHAMAR a função (aí sim ela executa)
let x = nomeDaFuncao(10, 20)
console.log(x)

Definir ≠ chamar. Só definir a função não faz nada acontecer — é como escrever a receita e deixar o caderno fechado. A função só roda quando você a chama, com os parênteses.

Tipo 1

Função sem passagem de parâmetro

Os parênteses ficam vazios: a função já sabe tudo o que precisa fazer, não precisa receber nada de fora. Mas atenção — mesmo vazios, os parênteses são obrigatórios na hora de chamar.

🎲 O gancho: por que sortearDado() muda toda vez?

Porque a função é executada de novo, do zero, a cada chamada. Ela não guarda o resultado anterior: chamou, roda tudo outra vez. Clique várias vezes no botão "Executar" do sortearDado() e veja.

Erro clássico: escrever console.log(ifal) sem os parênteses. Aí você não chama a função — você mostra a função inteira. O certo é console.log(ifal()).

Tipo 2

Função com passagem de parâmetro

Agora a função recebe valores de fora para trabalhar. Digite os valores nos campos: a chamada se monta sozinha e o retorno aparece na hora.

🔗 Encadeamento: uma função comendo o retorno da outra

Esse é o ponto alto. Como IMC(peso, altura) devolve um número, dá para jogar esse número direto dentro de analisarIMC(...):

console.log(analisarIMC(IMC(peso, altura)))

O JavaScript resolve de dentro para fora: primeiro calcula IMC(70, 1.75) → 22.86, depois chama analisarIMC(22.86) → "🟢PESO NORMAL".

Armadilha nº 1

Parâmetro × Argumento — e por que a ordem importa

📌 Parâmetro

É o nome que aparece na definição da função. É uma variável local que já nasce com valor.

function estacao(dia, mes) {
    ...
}

diames só existem dentro da função.

🎯 Argumento

É o valor de verdade que você manda na chamada da função.

estacao(25, 12)

O 1º argumento cai no 1º parâmetro, o 2º no 2º. Sempre nessa ordem — o JavaScript não adivinha.

🌦️ A função estacao(dia, mes) da nossa aula

Essa é a função de verdade, copiada do arquivo funcoes/estacoes.js:

function estacao(dia, mes){
    if ((mes == 9 && dia > 21) || mes == 10 || mes == 11 || (mes == 12 && dia < 21))
        return "💐 PRIMAVERA"
    if ((mes == 12 && dia >= 21) || mes == 1 || mes == 2 || (mes == 3 && dia < 20))
        return "☀️ VERÃO"
    if ((mes == 3 && dia >= 20) || mes == 4 || mes == 5 || (mes == 6 && dia < 21))
        return "🍂 OUTONO"
    if ((mes == 6 && dia >= 21) || mes == 7 || mes == 8 || (mes == 9 && dia <= 21))
        return "☂️ INVERNO"
}

✅ Ordem certa

estacao(25, 12)

☀️ VERÃO

dia = 25, mes = 12 → 25 de dezembro.

❌ Ordem invertida

estacao(12, 25)

undefined

dia = 12, mes = 25 → não existe mês 25! Nenhum if foi verdadeiro, a função terminou sem return e devolveu undefined.

Guarde isso: estacao(25, 12) ≠ estacao(12, 25). Trocar a ordem não dá "erro vermelho" — dá resposta errada em silêncio, que é bem pior.

Armadilha nº 2

return × console.log

As duas "mostram" coisas, mas só uma devolve um valor. Compare as duas irmãs:

✅ Com return

function somaComRetorno(a, b) {
    return a + b
}

let r1 = somaComRetorno(2, 3)
console.log(r1)
console.log(somaComRetorno(2, 3) * 10)

⚠️ Só com console.log

function somaQueSoImprime(a, b) {
    console.log(a + b)
}

let r2 = somaQueSoImprime(2, 3)
console.log(r2)
console.log(somaQueSoImprime(2, 3) * 10)

O que a diferença significa na prática

returnconsole.log
Para que serveDevolver um valor para quem chamouMostrar algo na tela
Dá para guardar numa variável?✅ Sim❌ Não (vem undefined)
Dá para usar numa conta?✅ Sim❌ Não (undefined * 10 = NaN)
Dá para encadear com outra função?✅ Sim❌ Não
Encerra a função?✅ Sim, na hora❌ Não, o código continua

Regra de bolso: se você quer usar o resultado depois (guardar, somar, comparar, passar para outra função), a função precisa de return. Se é só para aparecer na tela, console.log resolve.

Armadilha nº 3

Escopo — o que existe dentro e fora da função

Cada função é uma caixinha fechada. O que nasce lá dentro, morre lá dentro.

🌍 FORA DA FUNÇÃO (escopo global)

nomeDaTurma = "911C" — existe no arquivo inteiro, inclusive dentro da função.

🔒 DENTRO de calcularTotal(preco)

preco (parâmetro: variável local que já nasce com valor)
imposto (variável local, criada com let)

Aqui dentro dá para usar tudo: preco, imposto e também nomeDaTurma.

Aqui fora, imposto simplesmente não existe.

let nomeDaTurma = "911C"

function calcularTotal(preco) {
    let imposto = preco * 0.1   // local: só vive aqui dentro
    return preco + imposto
}

console.log(calcularTotal(100))   // 110
console.log(imposto)              // 💥 e agora?

Por que isso é bom? Porque você pode usar o nome i, total ou n em várias funções sem uma atrapalhar a outra. Cada caixinha tem as suas.

Bônus: o parâmetro é uma cópia

function dobrar(n) {
    n = n * 2       // muda só a cópia lá dentro
    return n
}

let valor = 5
console.log(dobrar(valor))  // 10
console.log(valor)          // 5 — o original não mudou!

O coração da revisão

🔁 A mesma função em 4 versões

Uma única ideia — calcular a área de um quadrado — escrita de quatro jeitos diferentes. Compare e veja por que a versão 4 é a "profissional".

Clique em Executar em cada versão — a tabela comparativa lá embaixo vai se preenchendo.

❶ Sem parâmetro, valor fixo

function areaDoQuadrado1() {
    return 5 * 5
}
areaDoQuadrado1()
—

😕 Rígida: responde sempre 25, não importa o lado que você escolher.

❷ Com parâmetro

function areaDoQuadrado2(lado) {
    return lado * lado
}
areaDoQuadrado2(12)
—

🙂 Agora serve para qualquer lado. É o pulo do gato do parâmetro.

❸ Sem return, só imprime

function areaDoQuadrado3(lado) {
    console.log(lado * lado)
}
let x = areaDoQuadrado3(12)
—

😬 O número aparece, mas não dá para guardar nem reaproveitar: x fica undefined.

❹ Com parâmetro, return e encadeada

function areaDoQuadrado4(lado) {
    return lado * lado
}
function classificarArea(area) {
    return area > 100 ? "GRANDE" : "PEQUENA"
}
classificarArea(areaDoQuadrado4(12))
—

🤩 A versão completa: calcula, devolve e o resultado ainda alimenta outra função.

📊 Comparando as quatro

VersãoReutilizável?Aceita entrada?Devolve valor?Encadeável?

Moral da história: a função fica boa quando ela recebe o que precisa (parâmetro) e devolve o resultado (return). Aí ela vira uma peça de LEGO que encaixa em qualquer lugar.
